# 집안일 플래너 웹앱

## Context

매주 반복되는 일(빨래)부터 몇 달에 한 번 하는 일(에어컨 필터 청소, 창틀 청소)까지 주기가 제각각인 집안일을, 마지막으로 언제 했는지 기록하고 "지금 뭘 해야 하는지" 한눈에 보여주는 개인용 웹앱을 만든다. 지금은 로컬에서만 사용하지만 나중에 배포해서 폰으로도 접속할 계획이므로, localStorage가 아니라 실제 파일 DB를 쓰는 구조로 처음부터 만들어 나중에 마이그레이션 비용을 줄인다.

## 결정된 요구사항 요약

- 사용자: 혼자 사용, 지금은 로컬 PC에서만, 나중에 폰 접속을 위해 배포 예정 (배포 자체는 이번 범위 아님)
- 항목별로 자유롭게 주기 설정 (N일 / N주 / N개월)
- 항목 추가/수정/삭제 자유롭게 가능 (CRUD)
- 카테고리 구분 없음 — 단일 목록
- 완료 취소(undo) 기능 없음 — 실수하면 항목 수정 화면에서 날짜를 직접 고치면 됨
- 홈 화면은 "마감일이 지난 항목만" 표시 (마지막 완료일 + 주기로 계산)
- 초기 시드 데이터 없이 빈 상태로 시작, 사용자가 직접 항목을 추가

## 기술 스택

- **Next.js (App Router) + TypeScript**
- **SQLite** (`better-sqlite3`, 프로젝트 루트에 `data/db.sqlite` 파일로 저장) — Route Handler에서 직접 쿼리
- **Tailwind CSS** 스타일링
- 로컬 실행 시 `next dev -H 0.0.0.0`으로 켜면 같은 와이파이의 폰에서도 바로 접속 가능

## 데이터 모델

`chores` 테이블 (단일 테이블, 완료 기록 히스토리는 별도로 두지 않음 — undo/히스토리 뷰가 필요 없다고 확정했으므로 YAGNI):

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | integer PK | |
| name | text | 항목 이름 (예: "빨래") |
| interval_value | integer | 주기 숫자 (예: 3) |
| interval_unit | text | "day" \| "week" \| "month" |
| last_done_at | text (ISO date, nullable) | 마지막 완료일. null이면 "한 번도 안 함" → 항상 마감일 지남으로 취급 |
| created_at | text (ISO datetime) | |

다음 마감일 계산: `last_done_at`이 없으면 즉시 due. 있으면 `date-fns`의 `addDays`/`addWeeks`/`addMonths`로 `last_done_at + interval`을 계산해 오늘과 비교 (달력 기준 계산이라 "3개월마다"가 정확함).

## 화면 구성

### 1. 홈 (`/`)
- 마감일이 지난 항목만, **가장 많이 초과한 순**으로 정렬해 카드 리스트로 표시
- 각 카드: 항목 이름, "마지막으로 한 지 N일 지남" 같은 초과 일수, "완료" 버튼
- "완료" 클릭 → 오늘 날짜로 `last_done_at` 업데이트 → 목록에서 즉시 사라짐 (optimistic update)
- 지난 항목이 하나도 없으면 "지금 할 일이 없어요" 안내
- 항목이 아예 없으면 (`/chores`로 이동해 추가하라는) 빈 상태 안내

### 2. 전체 목록 (`/chores`)
- 모든 항목을 다음 마감일이 가까운 순으로 표시 (D-day 형태, 이미 지났으면 "D+N"으로 강조)
- 항목 추가 폼 (이름, 주기 값 + 단위)
- 각 항목 인라인 수정(이름/주기/마지막 완료일 직접 수정 — 이게 사실상의 "취소" 수단) 및 삭제

## 파일 구조 (핵심만)

```
app/
  page.tsx                 # 홈 - 마감 지난 항목 목록
  chores/page.tsx           # 전체 목록 + 추가/수정/삭제 UI
  api/chores/route.ts        # GET(목록), POST(추가)
  api/chores/[id]/route.ts   # PATCH(수정, 완료 처리 포함), DELETE
lib/
  db.ts                     # better-sqlite3 초기화 + 테이블 생성(마이그레이션)
  chores.ts                 # due-date 계산 등 순수 로직 (테스트 대상)
  types.ts
```

`lib/chores.ts`의 마감일 계산 함수는 UI/DB와 분리된 순수 함수로 만들어 유닛 테스트하기 쉽게 한다.

## 검증 방법

- `lib/chores.ts`의 due-date 계산 로직에 대해 유닛 테스트 작성 (day/week/month 각 케이스, `last_done_at` null 케이스, 정확히 마감일 당일인 경계 케이스)
- `npm run dev`로 로컬 실행 후 브라우저에서:
  1. `/chores`에서 항목 추가 (예: 빨래, 1주마다)
  2. 홈에서 해당 항목이 바로 뜨는지 확인 (아직 완료 기록이 없으므로 즉시 due)
  3. "완료" 클릭 → 홈에서 사라지는지 확인
  4. `/chores`에서 다음 마감일이 오늘+7일로 표시되는지 확인
  5. 항목 수정/삭제 동작 확인
- 같은 네트워크의 폰 브라우저로 `http://<PC의 로컬 IP>:3000` 접속해 반응형 레이아웃 확인
