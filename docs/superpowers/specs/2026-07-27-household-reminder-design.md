# 생활용품 교체주기 리마인더 — 설계 문서

- 날짜: 2026-07-27
- 상태: 승인됨

## 배경

사용자가 제공한 "생활용품 30가지 교체 및 관리 주기 총정리" 이미지를 바탕으로,
각 항목을 클릭하면 그 항목의 교체/관리 주기가 리셋되는 웹 리마인더를 만든다.

## 목표

- 이미지와 동일한 레이아웃(5개 카테고리 컬럼, 컬러 헤더, 항목별 카드)을 HTML/CSS로 재현한다.
- 항목 카드를 클릭하면 확인 후 "마지막 교체/관리일"이 오늘로 리셋된다.
- 주기가 지난 항목은 카드에 작은 느낌표 배지로 표시된다.
- 서버, 로그인, 빌드 도구 없이 정적 파일만으로 동작한다.

## 비목표 (YAGNI)

- 여러 기기 간 동기화 (localStorage만 사용, 브라우저별로 독립)
- 푸시 알림/이메일 알림
- 사용자별 커스텀 주기 설정 UI (하드코딩된 기본 주기만 사용)
- 오프라인 캐싱(Service Worker) — 정적 페이지라 필요 시 나중에 추가 가능

## 기술 스택

빌드 도구/프레임워크 없이 순수 파일 3개로 구성한다.

- `index.html` — 마크업 (5개 컬럼, 항목 카드)
- `style.css` — 이미지의 컬러 테마(욕실=파랑, 주방=초록, 침실&리빙=핑크, 개인관리=보라, 가전&설비=청록)를 재현
- `script.js` — 데이터 정의, localStorage 읽기/쓰기, D-day 계산, 클릭 인터랙션

정적 파일이므로 파일을 더블클릭해서 열거나 GitHub Pages 등 아무 정적 호스팅에 올리면 바로 동작한다.

## 데이터 모델

각 항목은 다음 필드를 가진 객체로 `script.js`에 하드코딩한다.

```js
{
  id: "toothbrush",       // localStorage 키로 사용되는 고유 id
  category: "bathroom",   // bathroom | kitchen | bedroom | personal | appliance
  name: "칫솔",
  icon: "🪥",
  cycleDays: 90,          // null이면 "조건부/사용량 기준" 항목 (아래 예외 참고)
  cycleLabel: "약 3개월"   // 카드에 그대로 보여줄 원본 텍스트
}
```

`localStorage`에는 `{ [id]: "YYYY-MM-DD" }` 형태로 항목별 마지막 리셋 날짜만 저장한다.

### 예외 처리: 고데기, 향초

"고데기"(탄내/열 약해지면 교체)와 "향초"(시간 사용량 기준)는 달력 일수로 환산할 수 없다.
이 두 항목은 `cycleDays: null`로 두고, D-day/배지 계산에서 제외한다. 카드에는 원본 문구와
"마지막 교체일: YYYY-MM-DD"만 표시하며, 클릭하면 다른 항목과 동일하게 확인 후
`lastDoneDate`만 갱신된다(배지는 절대 뜨지 않음).

## 초기 상태 처리

앱을 처음 여는 시점(해당 id의 localStorage 값이 없을 때)에는 `lastDoneDate`를
**오늘 날짜로 자동 초기화**한다. 그래야 첫 방문 시 30개 카드에 전부 초과 배지가
뜨는 것을 방지할 수 있다. 이후부터는 사용자의 클릭으로만 갱신된다.

## D-day / 배지 로직

```
dueDate = lastDoneDate + cycleDays
남은일수 = dueDate - 오늘
```

- `cycleDays`가 `null`인 항목: 배지 없음, D-day 표시 없음.
- 남은일수 <= 0: 카드 우상단에 ❗ 배지 표시 (초과).
- 남은일수 > 0: 배지 없음.
- 마지막 교체일과 D-day(또는 "N일 남음")는 카드를 hover/탭했을 때만 툴팁으로 표시한다.

## 레이아웃

이미지와 동일하게 5개 컬럼을 가로로 배치하고(모바일에서는 세로로 쌓임), 각 컬럼은
고유 색상 헤더를 가진다.

| 컬럼 | 헤더 색상(이미지 참고) |
|---|---|
| 욕실용품 | 파랑 계열 |
| 주방용품 | 초록 계열 |
| 침실&리빙 | 핑크/레드 계열 |
| 개인관리 | 보라 계열 |
| 가전&설비 | 청록 계열 |

각 카드는 아이콘(이모지) + 항목명 + 원본 주기 문구를 표시한다. 아이콘은 이미지 속 아이콘을
그대로 잘라 쓰는 대신, 비슷한 느낌의 이모지로 대체한다(별도 이미지 에셋 불필요).

## 인터랙션 흐름

1. 사용자가 카드를 클릭한다.
2. 짧은 확인 토스트/팝업이 뜬다: "{항목명} 교체(관리) 완료로 표시할까요?"
3. 확인하면 `localStorage[id] = 오늘 날짜(YYYY-MM-DD)`로 갱신하고, 카드의 배지/툴팁이
   즉시 갱신된 상태로 다시 렌더링된다.
4. 취소하면 아무 것도 변경되지 않는다.

## 테스트 방침

빌드 도구가 없는 순수 정적 페이지이므로 자동화 테스트 프레임워크는 두지 않는다. 대신:

- `script.js`의 D-day 계산 함수(주기 계산, 배지 여부 판단)는 순수 함수로 분리해서
  브라우저 콘솔에서 수동으로 값 검증이 가능하게 만든다.
- 구현 완료 후 브라우저로 직접 열어 다음을 확인한다: 최초 로드 시 배지 없음, 클릭 → 확인
  팝업 → 리셋 동작, `cycleDays: null` 항목(고데기/향초)에는 배지가 절대 뜨지 않는지,
  localStorage를 수동으로 과거 날짜로 바꿨을 때 배지가 정상적으로 나타나는지.
